# Выгрузка материалов базы знаний

`crawler.js` снимает базу знаний **изнутри вашего браузера**: скрипт выполняется
прямо на странице, поэтому запросы идут с вашими куками и вашим доступом.
Ни пароля, ни ключей, ни копий профиля Chrome не требуется.

Файлы забираются **штатной кнопкой скачивания** сайта
(`/system/content/export/doc/<тип>/<id>/`), а не со страницы, — поэтому
сохраняется всё содержимое, включая таблицы и списки.

## Как запустить

1. Запустите локальный сервер (нужен, чтобы браузер не заблокировал загрузку скрипта):

   ```bash
   python3 serve.py 8765
   ```

2. Откройте в Chrome базу знаний, где видно дерево разделов.
3. Откройте инструменты: `Cmd+Option+I` (на Mac `F12` может переключать громкость).
4. Вкладка **Console**. Вставьте и нажмите `Enter`:

   ```js
   new Function(await (await fetch('http://127.0.0.1:8765/crawler.js')).text())()
   ```

5. В правом нижнем углу появится панель. Сначала **Диагностика**,
   потом **Начать обход**.

## Что делает

- **Диагностика** — раскрывает дерево разделов, считает разделы и статьи,
  проверяет отдачу файла и скачивает `kb-diagnostic.json`.
  Если `"fetchWorks": true` и `probe.ok: true` — обход пойдёт.
- **Отчёт API** — показывает, какие запросы сайт делает сам. Полезно, если
  обход ничего не находит.
- **Начать обход** — проходит по разделам, скачивает оригиналы с паузой 1,2 с,
  сохраняет заголовки, раздел, адрес источника и сам файл.
- **Стоп** — останавливает обход; уже скачанное не теряется.

## Куда складывается

Файлы скачиваются в обычную папку «Загрузки»:

```
kb-pages-ДАТА.ndjson   — по строке на материал:
                         url, source_url, title, section, fileName,
                         contentType, bytes, capturedAt
kb-files-ДАТА.zip      — оригиналы в папке files/
kb-images-ДАТА.zip     — картинки
kb-diagnostic.json     — отчёт диагностики
```

## Про формат файлов

Сайт отдаёт статью как `application/msword`, но внутри это **HTML с
вордовской разметкой**, а не бинарный `.doc`. Скрипт сохраняет такие файлы
с расширением `.doc` — Word и LibreOffice открывают их корректно.
Определение типа идёт по content-type, затем по сигнатуре байтов.

## Если обход прервался

Нажмите **Начать обход** снова. Байты файлов и их метаданные лежат в
IndexedDB браузера, поэтому уже скачанное не перекачивается.

Важно: документ считается скачанным только если в базе действительно лежат
его байты. Если запись есть, а файла нет, скрипт сообщит «без файла в
архиве: N» и перекачает их заново. Архив в конце собирается из всей базы,
поэтому в нём учитываются и файлы прошлых запусков.

Если нужно начать с нуля — удалите базу в DevTools → Application →
IndexedDB → `kb-crawl`, либо выполните в консоли:

```js
indexedDB.deleteDatabase('kb-crawl')
```

## Ограничения

- Скорость: 1,2 секунды между документами — чтобы не нагружать сервер.
  Обход нескольких сотен материалов занимает 10–15 минут.
- Картинки больше 5 МБ пропускаются.
- Разделы восстанавливаются из типа документа в адресе
  (`16` — налогообложение, `90` — кодексы и законы, `118` — шаблоны
  документов и т. д.), потому что сайт не отдаёт путь раздела в файле.
- `unzip` из macOS (версия 6.00 от 2009 года) портит кириллицу в именах
  файлов **любого** zip-архива, включая созданный Python. Это его давний
  дефект, а не проблема архива. Распаковывайте двойным щелчком в Finder
  или командой `ditto -x -k файл.zip папка/`.

## Обработка выгрузки

### Сначала проверьте выгрузку

При обходе эндпоинт `/system/content/export/doc/<m>/<d>/` может отдать
печатную версию **чужого** документа: заголовок берётся со страницы списка,
а байты — из ответа, и они расходятся. В `kb-final` так были все 455 файлов,
то есть заголовок не совпадал с содержимым ни у одного документа.

`repair-export.py` это чинит. Внутри печатной версии печатается заголовок
самой статьи, поэтому скрипт сопоставляет его с манифестом и перепривязывает
файлы к тем документам, которые они действительно содержат:

```bash
# посмотреть, что будет сделано, и список нерассчитанных документов
python3 repair-export.py ~/Downloads/kb-final --report

# собрать исправленную выгрузку (исходную не трогает)
python3 repair-export.py ~/Downloads/kb-final -o ~/Downloads/kb-repaired --apply
```

Документы, содержимое которых найти не удалось, получают в манифесте
`needs_refetch: true` — их нужно перекачать с вашими куками.

`import-kb.py` дополнительно сверяет заголовок страницы с заголовком внутри
файла и **не пропускает расхождения в корпус**: такой текст в статью не
попадёт, а в конце импорта будет список. Обойти это осознанно можно флагом
`--apply-mismatched`.

### Обычный импорт

В выгрузке лежат только `.doc` (внутри — HTML) со ссылками на картинки; самих
картинок нет. Сначала скачиваем их — они отдаются 1gb.uz без авторизации:

```bash
python3 fetch-images.py ~/Downloads/kb-repaired -o content/images
```

`import-kb.py` превращает выгрузку в контент основного проекта:

```bash
python3 import-kb.py ~/Downloads/kb-repaired \
  --manifest ~/Downloads/kb-pages-2026-09-28.ndjson \
  --images-dir content/images \
  -o content
```

Скрипт: восстанавливает расширения, убирает дубли по id документа
(выбирая самую полную версию), конвертирует HTML в Markdown с сохранением
заголовков, списков, **таблиц** (с учётом `colspan`/`rowspan`) и **картинок**,
раскладывает материалы по разделам и проставляет `source_url`.

Картинки кладутся в `images/` рядом со статьёй: сервер ищет `src` относительно
каталога статьи, поэтому общий `content/images/` он не увидит. Битые ссылки
вида `…/image/297///` (в самой выгрузке обрезан атрибут `src`) и служебные
иконки вида `/i/attach-locked.png` выбрасываются — на сайте они давали бы 404.

## Атрибуция

`source_url` сохраняется для каждого материала — это обязательное поле в
основном проекте, без него валидатор не пропустит публикацию чужих
материалов. Правда об авторе и источнике при выгрузке не меняется.

## Защита от чужих документов

Выгрузка 1gb.uz отдаёт заголовок со страницы списка, а внутри файла может
лежать другой документ. `import-kb.py` сверяет их и по умолчанию **не**
импортирует расхождения; посмотреть отчёт — `--dry-run`, форсировать
импорт — `--apply-mismatched`.

Правила сверки закреплены регрессионными проверками:

```bash
python3 tools/export-mcfr/test-import-guard.py
```

Там же зафиксированы два класса верных материалов, которые сверка однажды
отбросила: лид «Когда понадобит**ьс**я: …» (на сайте мягкий знак) и
подборки-заставки, у которых заголовок стоит в обложке-таблице, выбрасываемой
конвертером.

## Пересборка

`rebuild.sh` очищает `content/` (кроме кэша картинок) и кэш догруженных
документов перед сборкой. Это обязательно: `import-kb.py` и
`fetch-referenced.py` ничего не удаляют, поэтому без очистки статьи прошлой
битой выгрузки переживают пересборку и попадают в базу дублями одного
`source_url`.

## Что больше не работает

Пути через копирование профиля Chrome и отладочный порт оставлены в
`grab-session.sh` и `open-debug.sh`, но они упёрлись в шифрование кук
«Связкой ключей» и в то, что Chrome 136+ игнорирует отладочный порт на
обычном профиле. `session.mjs` и `probe.mjs` оставлены для диагностики.
Использовать `crawler.js` — проще и надёжнее.
